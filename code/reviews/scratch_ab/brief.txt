1 · Project overview
Toad City Baltimore is an open-world, cel-shaded street brawler set on Baltimore's Inner Harbor, built for
phones first. You play Harold, an elderly toad with a cane. His wife Mavis (grey afro, floral dress, a
handbag she swings) fights beside you under AI control. Together you clear crime out of each district
around the harbour. Each landmark district has a set-piece fight and a boss, and the final boss is Mister
Formstone. The real map is compressed about 3×: landmarks sit about one block apart, with a 6 m brick
promenade along the water and land about two blocks deep. Day turns to night every 5 minutes (a 600 s
loop), and at night the windows, street lamps and neon light up.

Tech stack
     three.js r160 with plain ES modules. The game source is a set of src/*.js files that a shell script
     concatenates into one module ( game.js ). There is no bundler and no framework.
     Everything procedural: geometry comes from three.js primitives in code, and every texture is drawn
     on a <canvas> at load. There are no image, model or font files to license. Audio is separate (not part of
     this work).
     Look: MeshLambert plus a 3-band toon ramp injected with onBeforeCompile , vertex colours, inverted-
     hull ink outlines and PCF soft shadows from one sun. A ?retro=1 32-bit mode exists, but the kit is HD-
     only and that is what you deliver for.
     How deliveries plug in: each module is a file that receives the kit object K (the same functions the
     game uses). In-house, we strip the export keywords, append the file to src/ , bind K to the game's
     globals and register the build function in the gang, boss, prop or vehicle tables. If your module runs in
     the kit viewer, it runs in the game.

Target devices and performance budgets
The main target is an iPhone in portrait, 390×844 CSS px at DPR 2 (the game view is the tall area
above the arcade panel), plus desktop Chrome and Safari. Aim for 60 fps, with a 30 fps floor on a mid-range
iPhone. Current city frames measure 76–168 draw calls and 99k–346k triangles at five spots (day,
390×844, including the shadow pass), so new assets must be lean.

Use mid-value base colours, because the toon ramp multiplies them by 0.46, 0.78 or 1.06. Never use pure
#000 or #fff: use INK #14101f for black and at most #f2f2f2 for white. Shadows are tinted slightly cool.

Toon ramp (cel bands)
     The lighting ratio r (lit luminance ÷ base luminance) is snapped to three bands: shadow 0.46 (r below
     0.38–0.44), mid 0.78 and lit 1.06 (r above 0.86–0.92). Edges are hard (smoothstep over 0.06).
     The shadow band is tinted by (0.88, 0.86, 1.10) at 50%. Strong local light (r above 1.35, such as a lamp
     at night) passes through unbanded.
     A hit-flash uniform mixes the whole rig to white ( mat.userData.flash ). Every sub-material of a rig must
     share it.

Ink outlines
     The outlines are inverted hulls: back faces of the same geometry pushed out along a mitred vertex
     direction ( odir , from addOdir() ), coloured INK #14101f .
     Width = uW × camera distance , with the distance clamped to 2.5–36 m. Characters 0.0042, city
     0.0034, props 0.0030. That gives a near-constant 2–3 px line on a phone, which fades into the fog
     colour with distance.
     Only major masses get hulls. Use outline: false on parts thinner than about 4 cm (characters) or 6 cm
     (buildings), and on flat decals. Never use screen-space edge detection.

 import * as THREE from 'three';

 const TAU = Math.PI * 2;
 const clamp = (v, a, b) => (v < a ? a : v > b ? b : v);
 const lerp = (a, b, t) => a + (b - a) * t;
 const damp = (a, b, r, dt) => a + (b - a) * (1 - Math.exp(-r * dt));
 const wrapA = (a) => { a = (a + Math.PI) % TAU; if (a < 0) a += TAU; return a - Math.PI; };
 const ease = (t) => t * t * (3 - 2 * t);
 const QUAL = { hd: true, outlines: [], texs: [] };   // the game runs HD by default; the kit is HD-only
 const INK = '#14101f';                              // the one ink colour: outlines, shadows on signs, dark trims

 // ---- toon (cel) material: MeshLambert + vertex colours + 3 hard bands + a hit-flash uniform ----
 function toonMat(opts = {}) {
   const m = new THREE.MeshLambertMaterial(Object.assign({ vertexColors: true }, opts));
   m.userData.flash = { value: 0 }; m.userData.flashC = { value: new THREE.Color(1, 1, 1) };
   m.onBeforeCompile = (sh) => {
     sh.uniforms.uFlash = m.userData.flash; sh.uniforms.uFlashC = m.userData.flashC;
     sh.fragmentShader = sh.fragmentShader
       .replace('#include <common>', '#include <common>\nuniform float uFlash; uniform vec3 uFlashC;')
       .replace('#include <opaque_fragment>', `
         { // HD cel bands: shadow 0.46 / mid 0.78 / lit 1.06 of the base colour, hard edges; shadows tinted cool
           float ld = max(dot(diffuseColor.rgb, vec3(0.299, 0.587, 0.114)), 1e-3), lo = dot(outgoingLight, vec3(0.299, 0.587, 0.114)), r = lo / ld;
           float b = mix(0.46, 0.78, smoothstep(0.38, 0.44, r)); b = mix(b, 1.06, smoothstep(0.86, 0.92, r)); b = mix(b, r, step(1.35, r));
           outgoingLight *= b / max(r, 1e-3);
           outgoingLight = mix(outgoingLight, outgoingLight * vec3(0.88, 0.86, 1.1), (1.0 - smoothstep(0.38, 0.44, r)) * 0.5); }
         outgoingLight = mix(outgoingLight, uFlashC, uFlash);
         #include <opaque_fragment>`);
   };
   m.customProgramCacheKey = () => 'psx' + (opts.map ? 'M' : '');
   return m;
 }

 function makeAtlas(tiles, size = 1024) {
    const c = document.createElement('canvas'); c.width = c.height = size; const x = c.getContext('2d'), R = {}; let ax = 0, ay = 0, row = 0;
    for (const [name, t] of Object.entries(tiles)) {
